# SQLite inputs

The evaluator databases in `human evaluators/` and `LLM evaluators/` are balanced exports in the original file locations. Each file has a `ratings` table and a `metadata` table. The default analysis reads these files. The duplicate-to-original row IDs and before/after counts are in [BALANCED_DATABASES.md](../../../BALANCED_DATABASES.md). The `observed/` directory stores the original evaluator databases for `analysis/reproduce.py --observed`.

`actors/` contains one database per application. TestReco and QuizComp link observer ratings to the original survey through the actor session ID. QuizComp uses a historical `llm_survey_responses` table name for its human replay ratings. WebArena links observer ratings by task session and validates the original two-task run. Human WebArena trace observers must have submitted both task surveys. TestReco uses the original Trust item for the paper’s Satisfaction column, QuizComp uses its combined satisfaction/trust item, and WebArena uses its separate Satisfaction item.

Human round files retain their source filenames and round boundaries. The observed human exports retain survey and assignment tables needed for reproducibility and use consistent pseudonyms within a database. The TestReco actor export retains only the education category used in constructing the prompt, linked to a pseudonymous actor. Independent description-only response rows have no actor link. Historical app databases and production credentials are separate from these exports.

`llm_coverage.csv` and `no_trace_inventory.csv` give observed coverage. The LLM trace protocol is `full-trace-role-context-time-blind-v2` at temperature 0.5. The stored source path in trace predictions is mapped to the packaged actor database. This keeps validation relocatable without changing the recorded scores. In particular, WebArena has incomplete LLM coverage across its 106 actor task surveys. The analysis validates the source cohort and excludes unmatched or duplicate evaluator responses. Saved prediction counts and matching decisions are detailed in the root `results/matching_audit.csv`.

The hashes in the package manifest apply to these reviewer exports. Source application traces, timestamps, and visual content may still need controlled access.
